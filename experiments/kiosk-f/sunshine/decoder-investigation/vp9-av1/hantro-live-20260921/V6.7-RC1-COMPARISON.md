# Exact v6.7-rc1 comparison

Upstream tag resolves to b85ea95d086471afb4ad062012a4d73cd328fa86.
Compared source, not a boot/runtime test of the old kernel.

- AV1 node in arch/arm64/boot/dts/rockchip/rk3588s.dtsi is byte-for-byte
  identical to the node in our test3 rk3588-base.dtsi. All four reset lines
  (A_AV1, P_AV1, A_AV1_BIU, P_AV1_BIU) already existed in v6.7-rc1.
- Original hantro_remove is byte-for-byte identical to our base test3 source:
  clock unprepare, assert reset array, disable autosuspend, disable runtime PM.
  Our experimental PM-order patch is a separate subsequent change.
- Both versions acquire the reset array and deassert it during probe. AV1
  compatible/variant and stateless controls are present in v6.7-rc1.
- Important PM difference: v6.7-rc1 rockchip_pd_power ignores the return values
  of idle-request and power-transition helpers and returns zero after the
  sequence. Test3 propagates these errors. The old helper can still log a
  timeout; ignoring its return is not proof of working hardware. No proposal
  to restore the old error suppression.
- Test3 also has clock-ungating and lock-management changes; source comparison
  alone cannot assign all behavioral differences to error propagation.
- AV1 decode differences include CDEF handling, transform mode mapping,
  tile-info allocation/column count, reference buffer refresh/offsets, intra
  frame classification and NV15 postprocessing. These later fixes are reasons
  not to substitute the old decoder blindly. See decoder diff.

Follow-up: split-reset module, retaining the PM-order patch. Test acquisition
validates the RK3588 compatible, four entries, each expected reset ID and CRU
compatible before operations. Default mask -1 retains ordinary array behavior.
Mask bits 0/1 are core A/P; 2/3 are BIU A/P. All four are deasserted on probe.
Only remove assertions are selectively masked. Probe-error cleanup still uses
all four and remains unqualified. This is diagnostic, not an image patch.
Apply split-reset patch after PM-order + stage diagnostics, INSTEAD of the
older keep-all-deasserted causal patch.

## Follow-up live results

Signed split-reset module on unchanged test3 kernel, no DT changes or reboot:

| Remove mask | Resets held after remove | Result |
|---|---|---|
| 0 | none | 3 clean cycles |
| 3 | decoder A/P only | 3 clean cycles |
| 12 | both BIU lines only | first cycle ready, second fails AV1 ACK/readiness |
| 4 | A_AV1_BIU only | first cycle ready, second fails AV1 ACK/readiness |
| 8 | P_AV1_BIU only | first cycle ready, second fails AV1 ACK/readiness |

Each failed series stopped at the readiness failure, before decode. This
implicates each held BIU reset individually under this runtime/PM sequence;
it does not prove the old v6.7 kernel failed identically (not booted).

After these failures, mask=3 completed three separate load/decode/unload runs.
Each produced 300/300 NV12 hashes matching the FFmpeg reference. Core reset
handling is retained, unlike the first experiment that omitted all resets.
Error-path reset policy and a proper permanent DT/driver ownership fix remain
open. No image recipe, default, or release workflow was modified.
Patch replay from pristine test3 with PM-order+diagnostic+split patches matches
both compiled files byte-for-byte. Module build passed.

The subsequent mask=3 Chromium/Wayland run ended normally: 7200 total frames,
1131 dropped (15.7%), V4L2VideoDecoder and platform decoder=true. This confirms
hardware use on this fixture, not smooth 1080p60 output. See the JSON summary.
After cleanup only kiosk-test remained running; hantro/v4l2-jpeg were unloaded
and all six temporary platform driver overrides were null. No reboot occurred.
