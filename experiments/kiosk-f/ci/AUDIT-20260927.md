### Do not dispatch the final integration build yet

The live test success still depends on a separate privileged Sunshine server and
bounded host setup. Source/runtime gaps remain explicit:

1. Native CLI still rejects Wayland remote access unconditionally. Replace only
   with appropriate capability/host checks after the complete runtime works.
2. Runtime advertises direct-RGA availability but leaves it disabled. No integrated
   policy yet selects the proven direct capture and manages its CSC prerequisite.
3. Existing kiosk configs lack /dev/uinput and the detected RGA device; setup only
   detects decoder/MPP/audio paths. Update-compatible reconciliation must preserve
   user selections and grant only required devices. Non-root access is also needed.
4. Input companion is staged and rotation derivation implemented, but same-container
   policy enable/disable/reconnect must be exercised. The live proof used explicit
   cross-container source and root. Dropping the CLI guard alone is insufficient.
5. Audio and non-root hardware-encoder operation must be rechecked in that assembled
   runtime, together with preserving pairing and Tailscale state. Physical SD
   first-install acceptance remains user-deferred.

Do not count a successful compiler/image run as closing these integration gaps.
Keep ordinary main A-D defaults and X11 capture available. The current audit
establishes preservation checks and readiness of build inputs, not readiness of
complete automatic F operation. No new build launched yet.
