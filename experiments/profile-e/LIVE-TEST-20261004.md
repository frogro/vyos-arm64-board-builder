# ROCK 5B live test, 2026-10-04

Kernel 6.18.54-vyos, existing A-D/F/G image, isolated new test services. No reboot
or replacement image was needed. Only the explicitly selected RX1 USB device
was passed to CUPS or VirtualHere; router network and touch devices were not
exported. The system clock was corrected and DNS supplied only to container
builds; no persistent first-boot network changes were made.

- CUPS 2.4 / Gutenprint 5.3.4 container built natively on ARM64.
- 3,631 `lpinfo -m` entries, including DNP and Citizen families.
- RX1 1343:0005 discovered via Gutenprint backend; loaded media reported 6x4.
- One 4x6 test page printed. User confirmed complete and correct. Remaining
  media changed from 500 to 499; printer returned idle with no pending jobs.
- HTTPS web UI returned 200. Protected configuration returned 401 without
  credentials and 200 with printadmin credentials.
- Recreated/restarted CUPS container retained RX1 queue and settings.
- Private container D-Bus and Avahi resolved initial ippfind discovery errors.
- Free generic VH 4.8.8 server / normal foreground Linux 6.0.3 client: RX1
  appeared on ThinkPad in `lsusb`, reported `IN USE BY: YOU`.
- Auto-use reconnected after server restart (tens of seconds, not instant).
- Native CLI rejected simultaneous CUPS USB-port and VH VID/PID assignment.
- Concurrent Moonlight H.264/Hantro stream: approximately five minutes,
  incoming/decode 60.01 FPS, rendering 59.98 FPS, network dropped 0.00%, jitter
  dropped 0.02%, average network latency 1 ms, no receiver service restarts.
- User also confirmed fluent visible video during the simultaneous VH test.
- Temporary stream and client stopped; VH disabled and RX1 returned to CUPS.
- Final systemd failed-unit list empty.

Initial prototype issues fixed: missing VyOS XML-reference registration, extra
newline in password input, missing mDNS infrastructure for driverless discovery.
The standard CUPS warning about future removal of legacy printer drivers is
still present; this prototype deliberately uses the current Gutenprint backend.

Limits: no Windows VH client, gamepad, physical print through VH, VPN path,
new-image/reboot/update test or additional board tested. The measured streaming
result demonstrates coexistence with one forwarded printer, not arbitrary USB
loads. This is not yet release-integrated profile E; see README for next steps.
