## Follow-up: device lifecycle and native CLI preparation

- Added a CUPS supervisor that grants only selected individual USB device nodes.
  Selection records physical port, VID/PID and a USB serial when exposed. The
  RX1 has no standard USB serial descriptor, despite its Gutenprint protocol URI
  containing a serial. Two identical RX1 units therefore cannot be distinguished
  at the same physical port by this implementation.
- Live software deauthorization/reauthorization of only `4-1.2`: grants changed
  from the RX1 node to none and back; CUPS returned with RX1 enabled/idle and the
  same queue URI. No job was sent. This was not a physical replug test.
- Synthetic USB tests cover device-number changes, replacement identity and
  disconnected/unauthorized devices; unrelated USB devices are never granted.
- Generic VirtualHere 4.8.8 was verified against its recorded SHA256 and ELF
  AArch64 header and installed under `/config/profile-e/virtualhere-bin`.
  Start and restart succeeded with an empty effective device allowlist (sentinel
  `ffff:ffff`); it was disabled again afterwards. Invalid download replacement
  and rollback-file preservation were tested separately without vendor binaries.
- Native E/shared-G source staging now generates one USB owner. Both XML files
  passed the schema and command-template generator from vyos/vyos-1x commit
  `fce6b4074f85a8112ba4de64bf2cee94eab704cd`. No manual cache patch is needed by
  this source preparation. Full package/build workflow integration remains open.
- Tailscale/WireGuard reachability was not tested: the fresh ROCK configuration
  currently has no active VPN interface. No VPN identity or routing was changed.

- Real native commits adding/removing a loopback allow-client succeeded; final
  active configuration was checked separately. A conflicting RX1 assignment to
  VirtualHere was rejected, and the active USB server remained disabled with
  its sentinel allowlist. The shell `commit` wrapper did not reliably expose
  failure through its process exit status, so the test checked the explicit
  diagnostic and active configuration instead.
- Final checks: CUPS HTTPS 200; protected configuration without credentials 401;
  RX1 idle/enabled; VirtualHere inactive; no failed systemd services.


## Native CUPS queue retention

A separate unshared `VYARM_OFFLINE_TEST` queue used the RX1 PPD and URI with
`printer-error-policy=retry-job`. With only the RX1 software-deauthorized, CUPS
accepted test job 2, reported "No matching printers found", retained the job
and kept the queue enabled. The test job and queue were deleted before USB was
reauthorized; no paper was consumed. CUPS already supplies the scheduler needed
for this case. USB ownership still requires explicit exclusive assignment.
